# 让门禁自己证明「它会失败」

## 判据（何时适用）

- 你刚写/改了一条审计判据（`E_*` / `W_*`、交付审计的某一项、`report.json` 的某个字段）。
- 判据的产物是「不一致单元 0」「内容一致 ✅」「三方一致 ✅」这类**全绿结论**。
- 你**没有**把一个真实缺陷注入进副本、看着它报错——那么这条判据目前只是一句断言。

典型失效形态（都在真实项目里发生过）：

| 写法 | 失效方式 |
|---|---|
| `if in_product and (n_blocks == 0 or n_blocks > 0) and present` | 恒真式：任何输入都成立，永远报 0 |
| `want in got or got in want` | 子串包含：成品被截短也算「一致」 |
| 两侧键口径不一致（`OEBPS/x.xhtml` vs `x.xhtml`） | 恒假：结构上不可能非零，于是永远「无问题」 |
| 只核**首文件**的 sha256 | 其余文件被改也不会发现 |
| 缺件时仍走「通过」分支 | 缺数据被当成「无差异」 |

## 处置

1. **一条判据 + 一条注入**：把工作区（或最小 fixture）复制成**临时副本**，按判据的语义
   注入一个最小缺陷，跑一次审计，断言**对应判据报错**、并且**基线副本零误报**。
   临时副本跑完即删，不碰真实工作区。

   ```text
   注入：从译文层删掉一个正文块（源层与对照表不动）
   期望：md↔align 漂移 ≥ 1 单元；块数差「未归因」≥ 1
   同时：未注入的基线必须 0 阻断级缺陷
   ```

2. **把注入清单写成表并落盘**（判据 → 期望报什么 → 「更正前的判据会怎样」）。
   这张表本身就是判据的说明书；后来者改判据时，先看它会不会让表里的期望失效。

3. **负向测试进 `tests/`**：只做正向（「干净输入通过」）的门禁等于没测。
   合成 fixture 要含**合法例外**（纯著录、外文引文、校勘标记、文件名式图注），
   否则下一次「零误报」是靠把判据写松换来的。

4. **判据口径要写进输出**：报告里带 `scope`（`not_run` / `sampled` / `full`）、
   `candidate` / `confirmed` / `resolved` 三态、抽样分母、规则/输入摘要。
   「默认 0」与「跑了并确认 0」在报告里必须长得不一样。

## 为什么门槛这么高

门禁的价值**全部**来自「它敢报错」。一旦某条判据恒真，报告就从证据变成
**最危险的假证据**：它比没有门禁更糟——没有门禁时人会自己抽查，有了假门禁，人会放心交付。

## 复现 / 验证

```bash
# 结构（以本项目为例）：一个独立脚本/测试，读真实或合成工作区
#   1) 复制 → 临时目录（tempfile；跑完删除）
#   2) 逐项注入 → 跑审计 → 断言「对应判据 level=error/blocking」
#   3) 还原 → 再跑一次 → 断言「零阻断级缺陷」
# 全部断言通过才返回 0

# 最小自检：把判据改成恒真式（如 `if True:`），注入项应当**不再报错** → 脚本必须失败。
# 这一步是「证明它会失败」的证明本身。
```
