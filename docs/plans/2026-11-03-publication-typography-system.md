## 1. 目标与交付定义

把前端的**设计系统、语义组件、渐进增强、响应式测试、视觉回归**用于出版物，建立
“内容结构 → 版式规则 → 实际渲染 → 独立验收”的闭环。

首期面向中文学术译著，涵盖中外文混排、密集注释、图表与索引；小说、诗集的特殊规则另行扩展，
但用诗行、RTL、代码作为防回归负例。首期不更换 PDF 引擎、不引入 React/运行时 JS、不重建编辑器。

交付物：

1. 版本化版式规则与两端参数映射，沿用现有主题及 PrintStyle 的公共入口。
2. 使用生产渲染链的合成样本册与静态预览目录；不是另一套手写演示模板。
3. 改善段落、标题、图表、注文、目录、页面角色的可验证增量。
4. DOM 几何、PDF 读回、截图与阅读器观察组成的报告；现有 G0–G5 门保持有效。
5. 一个具备源件及工作区的真实译本试点，在副本中完成前后比较及交付审计。

成功不是“截图更漂亮”：正文、注释、链接、图片保持完整；EPUB 经字号变化仍可读；
PDF 分页和页码正确；每项美化都有样本、规则和前后证据。

## 2. 当前实现与需要解决的问题

以下为源码观察，未在本轮做渲染复现，实施时先补最小样本。

| 现状 | 排版工程问题 | 归属 |
|---|---|---|
| `build/__init__.py` 内 `_STYLE_CSS + theme_css + book_css` 串接 | 规则分散，需明确基础、主题、组件例外、按书覆盖的优先级与输出来源 | P2/P3 |
| standard/spacious 给所有 `p` 设置缩进、对齐和段距 | 注文、引文、列表、图注可能受到正文规则影响；需计算样式验证，而非仅查字符串 | P1/P3 |
| compact 只显式设置部分属性 | 文档描述的“无缩进/左对齐”应验证实际继承及阅读器覆盖行为 | P3 |
| `bookcss.py` 有受限属性白名单，禁止 `@media/@font-face` 等 | 响应式功能应由内置样式负责，不靠开放任意书籍 CSS 实现 | P2/P4 |
| `pdfexport.py` 已有 PrintStyle、角色 class、图像高度预算 | 继续完善规则，不另设一套页面角色真相；尺寸预算应根据实际内容验证 | P5/P6 |
| PDF 全局 `p { overflow-wrap:anywhere }` 和 `figure, table, aside { page-break-inside:avoid }` | 已修缩放的兜底可能牺牲英文断词，长表/长注的整体避分页可能制造留白；先复现再细化 | P5/P6 |
| PDF 的 `blockquote` 字号低于正文，但内部 `p` 有显式正文字号 | 需检查子元素覆盖父容器的实际效果，统一组件文字规则 | P5 |
| `pdfdiagnostics.py` 已查纸张、字号、字体、溢出 | 补标题孤立、图注分离、非预期留白等证据；无需再造同类诊断器 | P7 |
| EPUB 规范限制具体字体、字号、颜色；按书样式与旧规范措辞存在差异 | 先明确“内置功能规则 / 有限主题 / 受限按书覆盖”，同步双语说明 | P0/P9 |

## 3. 借鉴前端的方法及出版边界

### 3.1 共享语义，分别呈现

```text
已确认的单元/内容结构
  → 生产 XHTML（标题、正文、引文、图注、表格、注文、索引、角色）
    ├→ EPUB：功能样式 + 有限主题 + 受限按书样式 → 阅读器
    └→ PDF：既有 EPUB 解析/转换 + PrintStyle → Chromium → 既有后处理
                ↓ 两端产物进入样本与诊断，同源身份对账
```

“组件”指稳定的语义标签及 class 契约，不意味着引入前端框架。
保持现有 PDF 从 EPUB 派生的链路，不另做绕过 EPUB 的直接构建路径。
正文阅读顺序以 DOM 为准，不靠 CSS order 重排，不用伪元素承载实质文本、注号或页码权威。

### 3.2 设计变量（tokens）只共享意图，不强行共享数值

| 变量族 | EPUB | PDF |
|---|---|---|
| 正文与注文 | 阅读器字号；generic family | 复用 body_pt/note_pt 与实际字体回落 |
| 段落节奏 | em 相对间距；主题可覆盖 | 以正文行高为参照的有限间距表 |
| 标题层级 | h1–h6 语义，保留用户字体控制 | 字号比例、段前后距、与后文同页策略 |
| 版心 | 跟随阅读区，不设整书固定宽高 | mm 页尺寸、边距及页眉页脚保留区 |
| 图像 | 等比例限宽，不裁掉内容 | 版心内高度预算，图注参与分页 |
| 断行 | 默认自然断行，长 URL 局部兜底 | 按语种/内容类型断行，实测无整书缩放 |

建议在构建时由 Python 数据结构生成普通 CSS；首期不依赖 EPUB 阅读器支持 CSS 自定义变量、
container queries 或 `@layer`。命名变量包含单位或明确无量纲。先保持旧默认值，再按样本调整。
公共配置不新增一个覆盖所有格式的任意 token 字典；需要新增选项时单独评审兼容性与摘要绑定。

### 3.3 渐进增强与失效状态

- EPUB：基础流式结构在关闭作者样式、放大字号、换字体、暗色模式时仍可访问。
- 图表等增强功能失效时保留全部数据和原图入口，不靠裁剪或整页截图掩盖溢出。
- 注释保持标准 noteref/aside/backlink；弹窗由阅读器决定，跳转/回链始终可用。
- PDF：Chromium 的 `avoid` 是分页约束，不是“绝不会拆页”的保证；长对象要有可拆分策略。
- PDF 首期沿用现有注文位置，不承诺真正逐页页底脚注；若要页底脚注，另做引擎能力验证与方案。

## 4. 样本册与验收矩阵

### 4.1 合成样本册

复用测试 fixture 构建器，新增 `tests/fixtures/typography/`（拟新增），全部使用合成文本。
至少覆盖下列 12 类，每类有稳定 case_id、期望结构、可自动判断项和人工观察项：

1. 章节开篇：长短题名、章号、副题、连续多级标题。
2. 正文：中短长段落，章节首段、标题后首段、普通续段。
3. 混排：中文、拉丁、俄文、RTL 引文、撇号、括号、混合强调。
4. 引文：单段与多段、引文内列表、引文结束后正文。
5. 诗行/编号段落/代码：空白和手动换行保真，非正文缩进不被污染。
6. 注文：短注、跨页长注、一注多引用、含链接与图表的注。
7. 图片：小图、宽图、高图、扫描图，短图注与超过一页的图注。
8. 表格：短表、多页表、长单元格、长 URL、合并单元格与表题表注。
9. 目录：长标题、三级层级、同名标题、两位转三位 PDF 页码。
10. 索引/书目：悬挂缩进、跨行条目、页码区间、两栏 PDF。
11. 书名页/部分页/版权页/封面：按已确认角色，包含无角色负例。
12. 极端输入：超长连续串、缺字体、无图片、字体替换、作者样式关闭。

每类既有独立组件页，也纳入一个足够长、自然跨页的整册；组件通过不代替整书分页通过。
浏览器预览直接取成品 XHTML/CSS，PDF 预览取实际 PDF 页图。预览壳的控制样式与正文隔离。

### 4.2 测试矩阵与成本控制

| 层次 | 最低范围 | 用途 |
|---|---|---|
| PR 快检 | Chromium，内容区宽 320/768 CSS px，默认与 200% 字号；关键组件 | 样式串扰、溢出和内容丢失 |
| 完整浏览器组 | 320/600/768，三主题，默认/200%字号；暗色与字体替换用代表样本 | 边界组合，不做无意义全笛卡尔积 |
| EPUB 成品实测 | 至少两种不同渲染栈，例如 Thorium 与 KOReader；记录实际版本 | 分页、作者样式覆盖、注释往返、暗色模式 |
| PDF | 当前 A5 与32开配置，默认及一个较大正文字号，真实 Chromium 输出 | 纸张、版心、分页、目录及书签 |
| 真实译本 | 先一本，再扩到图表多/注密集/混排三类 | 整体阅读节奏与真实复杂度 |

浏览器宽度模拟不是电子墨水设备实测；同一引擎的两个软件不算不同渲染栈。
环境缺失记 unknown，报告列实际运行与未运行组合。现有产品放行规则不因本计划自动改变；
本轮“跨阅读器排版验证完成”的声明要求对应实测记录齐全。

## 5. 质量标准与证据

### 5.1 硬条件

- 原有 G0–G5、EPUBCheck、注释/媒体/目录/内容对账全部通过。
- 合成样本正文/注释/图片/链接身份与预期一致；样式调整不改文本、段落或源译对应关系。
- EPUB 普通正文在矩阵内无整页横向溢出、遮挡、裁字；复杂表格例外必须记录可访问路径，
  所有单元格内容完整。DOM `scrollWidth` 只作线索，必须结合文字 Range/截图检查。
- PDF 沿用现有字号/纸张/溢出容差，不为新样式调宽标准；图像比例保真、图注完整。
- 目录、书签、正文锚点的最终页序精确一致；分页改变须重跑收敛与 manifest 校验。

### 5.2 首期视觉指标（拟定，P0 冻结）

| 指标 | 判据 | 证据/限制 |
|---|---|---|
| 标题孤立 | 能容纳时，标题后至少同页两行正文；样本违规为0 | PDF 位置与页图复核；超长标题单列 |
| 孤行寡行 | 普通段落跨页尽量两端至少2行 | `widows/orphans` + 实际读回，超长不可分对象单列 |
| 图注关系 | 短图注与图同页；长图注首段随图且后续顺序完整 | 图 bbox、文字映射与页图 |
| 异常留白 | 普通正文页底空白超过版心高度30%时报告候选 | 章末/部分页/图版页排除；不是自动判错 |
| 断词与节奏 | 普通拉丁单词避免任意字符断行，长 URL 可断；无持续异常字间拉伸 | 样本前后对照，人工结论留理由 |
| 缩进层级 | 正文、引文、注释、表格、索引各自一致且互不串扰 | 计算样式与 PDF 读回 |

几何重叠可能来自合法上标、行内强调或字体度量；先给候选，经负例稳定后再升级门禁。
截图差异率不是质量分数。固定 OS/字体文件摘要/浏览器版本/DPI/视口/样本摘要后，
对同环境 baseline/candidate/diff 比较；跨环境变化先标不可比，不自动覆盖黄金图。
批准新基线须写明 case_id、差异原因、相关提交与人工复核结论。

报告最小字段：schema_version、revision、输入/EPUB/PDF/CSS摘要、工具和字体身份、
case_id、target、viewport或page_size、实际测试状态、问题定位（unit/anchor/page/bbox）、
预期/实测、证据路径、处置。未知和跳过不折算通过。

## 7. 顺序、里程碑与回滚

```text
P0 → P1 → P2 ─┬→ P3 → P4 ─────────────┐
               └→ P5 → P6 ─────────────┤→ P8 → P9
     P1 → P7a → P7b（另依赖P5）────────┘
```

- M1（P0/P1/P2）：规则有出处、样本可重复，先交付“看得见当前问题”的基线。
- M2（P3–P6）：每次只改一类组件，提交前展示同一case的旧新效果，保持全文对账通过。
- M3（P7/P8）：把人工发现沉淀成可定位的检测；冻结受支持环境与基线审批规则。
- M4（P9）：实书试点通过后才建议替换交付批次；旧EPUB/PDF及manifest保留便于回退。

P3/P4 与 P5/P6 在契约冻结后可分工；共享渲染模型和 `pdfexport.py` 的任务顺序合入。
这是工作拆分建议，本轮不启动子agent。预计10–14个小提交；不以固定工时承诺替代失败复现。

回滚按提交/版式版本进行，不修改源文以适配旧版式。样式变更重新生成产物并重跑摘要及QA，
历史已发布记录不覆盖；新旧文件分目录，禁止用新图覆盖旧基线后宣称零差异。
