## 2. 原 PR 八类缺陷：证据与修复

| 类别 | 已发现的缺陷/反例证据 | 修复契约 |
|---|---|---|
| 1. 术语豁免不可追溯 | 原题/引文保留需要区别于真实误译，单纯忽略命中不能提供核证理由，也不能使旧报告可靠失效 | 可选 `preprocessing/terminology_exemptions.csv`，表头 `unit,source,reason`；精确单元+规范源词，理由必填；完整空行跳过、部分行报错。三个入口均明示非阻断命中及理由；G0/QA 的 `terminology_exempt` 数据含 `reason`；增删改使摘要失效 |
| 2. 空 align / 纯标题判定与状态推进 | 缺源、空源、标题后紧接正文或译文额外正文不得当作纯标题；强制重验失败不能再被 reviewed 提升掩盖 | 两侧现有非空文件均只含规范 ATX 标题和空行才可空 align，仍核对层级；共享 import/G0/QA 判定，`import --reviewed` 同次推进新校验单元，失败重验不回升 |
| 3. 引用与数学/OCR 混淆 | Unicode 上标可能是数学；引号/省略号后真实注码不能自动当噪声；中文邻接引用与数字规模短语需区分 | 保留 `[^label]` / `[^ref-ID]`，不得以上标抵消缺失引用；含混处由 agent 取源证据修复并登记注释图，不用宽泛正则压掉告警 |
| 4. 注释编号与正文覆盖混淆 | 旧式源 label `7` 可合法显示为 `[1]`；注文不能补足邻接丢失正文 | 不将源 label/ref_id 等同显示编号；真实语义 noteref/footnote/endnote 从正文覆盖排除，由独立注释门负责内容与链接；字面代码、数学上标仍算正文 |
| 5. 标题块吞正文与字面井号误清理 | 标题后紧跟正文不能随标题跳过；表格 `# 1`、行内代码 `# comment` 不是清理对象 | 仅识别真实语法边界，保留正文、表格与代码中的字面字符，不以标题/注码清理吞内容 |
| 6. 围栏代码被当成结构或资源 | 代码可展示 HTML、标题、媒体路径、脚注、锚点与容器标记，不应生成导航、媒体读取或残留 | 普通围栏转义显示；显式 Pandoc raw HTML 单独处理。source/G0/render/QA 共用 `auto_common/markdown.py` 纯语法 helper，translator 不依赖 epublizer |
| 7. SVG 命名空间与成品声明 | 内联 SVG 必须是有效 XML/SVG，不能靠转义或静默丢弃未绑定前缀“通过” | 真实 SVG 命名空间，所属内容 manifest 项声明 `svg`；未绑定前缀失败，代码中的 SVG/img 不作为资源 |
| 8. 媒体身份与路径核对 | 同 basename 异目录媒体不能替代真正缺失资源；SVG 本地 image 资源也须核对 | href/xlink:href 按完整路径身份处理，HTML URL 只解码一次，ZIP 名按字面；源/ZIP 缺资源、越界或符号链接逃逸阻断放行 |

## 3. 额外真实发现：source ingest 围栏边界

修复过程中发现源文本/Pandoc 摄入会按空行切分围栏，进而把围栏内假标题拆成章节，或把
独立数字送入页码清理。仅修渲染器不足以恢复已经在 ingest 丢失/重切的内容。因此源摄入也
须跨空行保持整段围栏，内部标题与数字均为代码，不产生章节边界或页码清理。
