# 2026-09-29 成品导航层级：单元内锚点目录 + 标题层级保真与守恒

状态：已完成（6b3acb7）

## 背景

成品 EPUB 的目录（nav/NCX）只有**单元级**条目——一条目录链一个 `file.xhtml`。四个来源的层级
信息在链路上被逐级丢弃，导致「源文有层级、目录全扁平」：

1. **PDF 书签只取 level-1**（`pdf_reader._level1_toc` 直接 `continue` 掉 level≥2），
   子级标题既不进正文也不进单元 meta；
2. **聚合单元内标题段一律压平为 `##`**（`structure/rebuild._render_markdown`），
   原层级丢失；
3. **nav 只有单元级条目**，无单元内子标题锚点——epub-template-spec §「目录为单元级嵌套，
   无单元内子标题锚点需求」的设计假设本身即扁平；
4. **g0 不校验标题守恒**（issue #12：`count_heading_levels` 在 review/g0.py 存在但未接线），
   译文丢标题/换级无门检出（现场报告 #10-B1：ch10 丢 2 个 `###`、ch04 换级 6 处，
   `g0_structure_open=0` 照样通过）；
5. **E_TOC_FLAT 检不出「源文链本身平」**：只在单元 level 链有深度而 nav 平时报错；
   PDF 路径源文链全为 1 → 静默放行。

既有基础设施（本轮全部复用）：html.py 的 `{#id}` 标题 id 与 `[]{#id}` 行内锚点、
`output.nav_depth` 深度投影、restructure 的 structure.csv level 字段、MinerU
`text_level` → `heading_level` 链路。

## 目标

- 目录条目下探到**单元内子标题锚点**（`file.xhtml#anchor`），深度受既有 `nav_depth`
  投影约束（超深不进目录、保留在 spine）；
- 层级信息在 ingest→structured→translation→build→qa 全链路**保真**（PDF level≥2
  书签、标题段原层级）；
- g0 新增**标题守恒**硬门（issue #12）；
- qa 目录对账扩展到锚点级，E_TOC_FLAT 能检出「单元链平但正文有子标题」的书。

## 技术设计

### S1 g0 标题守恒（`review/g0.py` + 接线）

- `g0_unit_flags` 新增 `translation_md: str | None = None` 参数；与 `structured_md`
  同时给出时执行 `count_heading_levels` 逐层计数对账，不一致 →
  `G0Flag("heading", "标题层级数量不守恒", {"src": {...}, "tgt": {...}})`。
  h1 计入（structured 首行 `# 单元题` 应在译文中镜像；缺 h1 会使
  `unit_heading` 回落到更深标题）。
- 接线三处调用点（orchestrator）：`import_translations`（读 `tgt_path` 内容传入；
  归入 warned 告警，与 marker/footnote 同级）、`g0_check`、`_collect_g0_flags`。
- `qa/report.py` 的 `g0_structure_open` 计数集合加入 `"heading"`（放行硬门：
  标题丢失=目录节点在成品中消失，真实缺陷）。

### S2 锚点级 nav（`build/html.py` + `build/__init__.py` + `orchestrator`）

- **html.py 自动稳定 id**：`markdown_to_xhtml` 标题分支（level ≥ 2 且给了
  `unit_id`）——每遇一个 level≥2 标题计数 `n += 1`（**含显式 `{#id}` 者**，
  保证与扫描器一致）；无显式 id 时补 `id="{unit_id}-h{n}"`。h1 与
  `unit_id` 为空时行为不变。
- **纯函数 `subheading_anchors(md, unit_id)`**（放 build 包，html.py 同款块遍历
  语义：按空行切块、块首行 `_HEADING_RE` 匹配、`_split_heading_id` 剥
  `{#id}`）：返回 `[{level, title, anchor}]`，anchor 与 html.py 渲染产物
  **逐字一致**（nav 只会指向真实存在的锚点）。
- **nav/NCX 树**：entries 可携带 `anchors` 列表；`nav_toc_entries` 投影时锚点
  深度 = 单元深度 + `_toc_depths(anchors)` 相对深度，超 `nav_depth` 剔除（单元
  被剔除 ⇒ 其锚点一并剔除）。`_toc_tree` 把锚点子树**前插**为单元节点的
  children（阅读顺序：单元文档内锚点先于子单元文档）。`_render_nav_items` /
  `_render_ncx_points` 渲染 `file.xhtml#anchor` 条目；`_render_ncx` 的
  `dtb:depth` 取含锚点的最大深度。
- **orchestrator `_render_and_pack` 挂接**：非双语路径在 `md_text` 读入后
  `e["anchors"] = subheading_anchors(md_text, e["id"])`（译文优先、
  structured 回退——与渲染源一致）。**双语文档不挂锚点**（双语页由 align 行
  渲染、不含子标题，挂了就是悬空链接）。
- audit.py 无需改：E_NAV_HREF 的 href 正则不匹配带 `#fragment` 的链接；
  E_TOC_COVERAGE 已按 `href.split("#")[0]` 对账。

### S3 qa 目录对账扩展（`qa/provenance.py`）

- 新增 `nav_depth_sequence(entries)`（build 包导出）：`_toc_tree` 先序遍历的
  完整深度序列（单元 + 锚点），build 与 qa **共用同一实现**（防漂移）。
- `audit_provenance` 的期望集循环：按 build 同款 `md_path` 计算
  `e["anchors"]`；TOC 对账段按 `doc_bilingual` **豁免双语文档的锚点**
  （与 S2 的挂接策略镜像）。
- `toc_depths_expected` 改用 `nav_depth_sequence`（含锚点）；
  `E_TOC_FLAT` 判定升级为「期望序列（含锚点）深度 > 1 而 nav 实际为单层」
  ——检出断点 5（单元链平但正文有 `##`/`###` 子标题的书）；
  `W_TOC_DEPTH` 对账两侧同为锚点级序列。

### S4 ingest 层级保真（`pdf_reader.py` + `structure/rebuild.py` + `epub_reader.py`）

- **pdf_reader**：新增 `_apply_sub_toc(segs, subs)`——level≥2 书签落在其章
  page_range 内：① 定位 = 首个 `source_page ≥ 书签页` 的段；② 书签标题与该段
  文本**全等** → 原段升级为 `KIND_HEADING`（meta `heading_level`）；③ **子串**
  → 段内切分为「标题段 + 余文段」（防整段误升）；④ 无匹配 → 在定位前**插入**
  新标题段（书签无 y 坐标，页边界是确定性最优近似，误差由 restructure 修）。
  处理后单元内 `index` 重排。
- **rebuild._render_markdown**：标题段按 `s.meta.heading_level`（缺省
  `mineru_text_level`，再缺省 2）写 `#{level}`，夹取 `[2, 6]`（每文档恰好一个
  h1 由单元 `# 行`保证）。
- **epub_reader._blocks_to_segments**：标题段携带
  `meta.heading_level = len(m.group(1))`（原 `#` 数即层级）。

## 边界与不变量

- `nav_depth` 投影语义不变（1–6；超深不进目录、保留 spine 与锚点）；
  `nav.xhtml` 的 `<meta name="nav-depth">` 声明不动。
- 锚点 id 命名 `{unit_id}-h{n}`：文档内唯一（epubcheck 合法）、确定性（同 md
  两次构建一致）、不与既有 `{#id}` / `[]{#id}` 冲突。
- 旧工作区兼容：结构未变（只加 id 属性与 nav 条目）；S4 改变 structured 输出，
  已有工作区需重跑 `preprocess` 才受益（幂等重建，状态不受影响）。
- 双语构建（`-bi.epub`）不含锚点条目（渲染源无子标题），qa 期望侧同步豁免。
- 守恒类检查均为**单元级总量比对**（与 marker/footnote 同型），容忍句级拆并。
