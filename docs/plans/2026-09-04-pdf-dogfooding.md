# 计划：真书 dogfooding——PDF 内容提取管线实战验证

> 状态：**已完成**（2026-09-04；验证记录见 §6。三类机制全部实测通过，暴露并修复 5 个
> 真实缺陷；全书 OCR 批量转换（~28s/页）标注为后续批处理任务，不在本计划内）。
> 前置：计划 C（S2–S4）已落地，但只过了合成 fixture 测试；阈值与判据未经真实书籍检验。

## 1. 背景与问题

新管线的能力——书签 TOC 切章、多栏阅读顺序、插图路由（整页/内嵌/扫描背景守卫）、
表格双路径、公式三特征检测、inserts 溯源审计——全部只在 `tests/` 的合成 PDF 上验证过。
合成 fixture 无法暴露：真实排版的字 号分布、伪书签（目录级书签 vs 正文书签）、
表格线残缺、公式字体多样性、扫描件混合文字层等真实情况。

## 2. 选书标准（三类各至少一本）

| 类型 | 要求 | 验证重点 |
|---|---|---|
| 有书签 TOC 的文字层 PDF | level-1 书签 ≥ 5 条；章节页码准确 | 切章边界 vs 书签、frontmatter 归属、页码区间 |
| 含图表/公式的学术 PDF | 有线框表格、编号公式、插图 | 表格 md 质量/裁剪图触发、公式检测查准查全、多栏阅读顺序 |
| 扫描件（可选） | 无文字层或 OCR 文字层 | OCR 五档路由、扫描背景不提取、OCR 域不误触发整页路由 |

来源：本地藏书或用户提供的无版权文件；**绝不提交真实书籍文件进仓库**（测试一律 tempfile）。

## 3. 执行步骤

1. `auto-epublizer doctor [--ping]`——记录环境快照；
2. `auto-epublizer preprocess <book.pdf>`——读 facts.md（书签/扫描/乱码判定 +
   路由提示是否正确），按 skills 写 preprocessing/ 七件套；
3. `auto-epublizer init`（或 convert 只验 ingest）——检查 `structured/raw/`：
   - `page-NNN.json` blocks 顺序（双栏页人工比对阅读顺序）；
   - `raw/media/`：内嵌图/整页图/裁剪图的数量与命名（`pNNN-imgNN` / `pNNN-page.png`）；
   - `raw/inserts/`：id 命名、index.jsonl 快照、公式记录 `latex: null`；
4. `auto-epublizer convert`（不翻译，快速走 build + qa）——检查 EPUB 内图片、
   `qa` 的 inserts 审计发现与 `prov_ok`；
5. 抽查误报/漏报：表格检测误触发（把正文段落判成表格）、公式误报（居中短行）、
   插图漏提（内联小图 < 32px 被装饰过滤是否合理）；
6. 回填：确认/调整的阈值写回 `docs/pdf-content-spec.md` §7（改动走常规提交）；
   发现的缺陷按最小回归测试补 `tests/`。

## 4. 验收标准

- 三类书的验证记录（可写 `docs/testing-<book>.md` 或直接在本文档追加「验证记录」节）；
- spec §7 阈值与真实书的偏差已回填或有明确「维持默认」结论；
- 暴露的缺陷转化为可失败的回归测试并修复；全量回归 + ruff 双检通过。

## 5. 本轮不做

- 翻译/审校全流程（G1–G3）的实战验证——另一轮 dogfooding 单独立项
- 扫描书 OCR 语种/质量调优（依赖具体 OCR 引擎）
- 真实书籍文件入库（永远不做）

## 6. 验证记录（2026-09-04）

书源：`PDFs/`（.gitignore，不入库）。环境：pymupdf ✓ rapidocr ✓ epubcheck 5.2.1 ✓
（当日下载装 jar）网络 ✓；无 LLM Key（agent 路径）。

| 书 | 类型 | 验证内容 | 结果 |
|---|---|---|---|
| C语言教程（165p） | 文字层 + 16 条 L1 书签 | 书签切章 / 图 / 表 / 公式 / convert+qa | ✅ G5 放行；16 单元、62 真 md 表、4 内嵌图（含 p29 流程图） |
| On Lisp（426p） | 文字层无书签（TeX 排版） | 启发式降级 / 公式检测 | ✅ G4 pass；58 单元；公式误报 86→2 |
| 自由软件（366p） | 扫描件但带文字层 | 背景守卫 / 混合页 | ✅ 全书 0 媒体 = 本书本无栅格图；正文完整；G4 pass |
| 黑客与画家（262p） | 真扫描（0 文字层） | OCR 路由（rapidocr） | ✅ 8 页样张：封面/正文正确识别、OCR 页不触发整页路由；全书转换 ~2h 属批处理 |
| JS 权威指南（1018p） | 真扫描 | 同上（机制覆盖） | 未跑全书（同黑客与画家机制） |

**暴露并修复的缺陷（全部带回归测试）：**

1. `·`（人名间隔号）/`…`（省略号）被当数学符号 → 中文正文误判公式（C 教程 p1）——
   移出符号集，改纳 `⋅`(U+22C5)/`∗`(U+2217)（`e4f21db`）；
2. `orch.qa` 忽略 `config.qc.epubcheck.jar`（潜在潜伏 bug）+ 默认 `~` 路径不展开
   （pydantic v2 默认值不走 validator）——两处修复（`e4f21db`/`5cd5a8a`）；
3. TeX 正文书引号/尖括号 span 用 CMSY 字体 → 字体特征整段误判（On Lisp 86 条）——
   字体特征加占比守卫 `MATH_FONT_RATIO=0.5`（`0d47818`）；
4. OCR 页无媒体时 raw 目录不创建 → page json 写入崩溃——`read_pdf` 显式 mkdir
   （`0bd8adb`）；
5. find_tables 版面误检：边框代码盒被粘连成跨半页假表格（36/108 记录单格 >300 字符；
   p29 裁剪图吞掉流程图+正文）——双守卫 `TABLE_MAX_AREA_RATIO=0.5` +
   `MAX_TABLE_CELL_CHARS=300`（本提交）。

**视觉核对方法**：疑似页渲染 PNG 后由 agent 直接看图对账（p66 表格/代码边界、
p29 流程图归属），是本次定位缺陷 1/5 的关键手段。

**spec 回填**：`pdf-content-spec.md` §4（表格双守卫）、§5（符号集修订 + 占比守卫）、
§7（新常量）。
